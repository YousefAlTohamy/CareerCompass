# التشريح العميق لخطوات التنفيذ (Deep Execution Flow: IPO)

هذا الدليل مخصص لتشريح ما يحدث **بالضبط خلف الكواليس** في Layer 1، خطوة بخطوة بالترتيب الزمني الحرفي. لكل خطوة سنطرح: المُدخلات (Input)، ما يحدث داخلياً من خوارزميات وتقنيات (Processing & Algorithms)، والمُخرجات النهائية (Output).

---

## 🛠️ الخطوة الأولى: الاستخراج والانقضاض المكاني (Spatial Parsing)
📍 **الملف:** `spatial_parser.py`

- **الـ Input (المُدخلات):** 
  - `pdf_bytes: bytes` (السيرة الذاتية بصيغتها الصفرية الخام).
- **الخوارزميات والـ Processing (المعالجة):**
  - **التقنية المستخدمة:** مكتبة `pdfplumber` (المتخصصة في التحليل البصري والمكاني للـ PDF).
  - **الخوارزمية:** تعتمد على الهندسة التحليلية والإحداثيات الديكارتية (Cartesian Coordinates). الكود يستخرج كل كلمة مصحوبة بمواضعها `[x0, y0, x1, y1]`.
  - ثم تمر على خوارزمية **Clustering (التجميع النقاطي المكاني)** `_group_words_into_rows` لجمع الكلمات التي تقع على نفس خط العرض المكاني (Y-axis tolerance)، حتى لا تختلط خبرة جهة اليمين مع تواريخ جهة اليسار!
- **الـ Output (المُخرجات):** 
  - نموذج بيانات `SpatialTextExtraction` يحمل الـ `text` (النص المرتب من الأعلى للأسفل)، ورقم يمثل `word_count`، و `page_count`.

## 🚨 الخطوة الثانية: الإنعاش بنظام الـ OCR (اختياري - Fallback)
📍 **الملفات:** `orchestrator.py` و `ocr_pipeline.py`

- **الـ Input (المُدخلات):** 
  - النص المستخرج من الخطوة الأولى. إذا اكتشف `orchestrator` أن كثافة الحروف أقل من 150 حرف (`_MIN_CHAR_DENSITY`)، يُمرر الـ `pdf_bytes` للخطة البديلة.
- **الخوارزميات والـ Processing (المعالجة):**
  - **التكنولوجيا:** `PyMuPDF (fitz)` للتعامل مع الصور، و `EasyOCR` كعقل مدبر.
  - **الخوارزمية:** 
    1. يتم تحويل صفحات الـ PDF إلى مصفوفات بُكسلية مُلتقطة (Image Bytestreams).
    2. يُنفذ `EasyOCR` الذي يعتمد على شبكات عصبية التوائية (CNN) لالتقاط أماكن الحروف، وشبكات تكرارية (RNN/LSTM) للتنبؤ والنطق الإلكتروني للحروف من الصورة.
- **الـ Output (المُخرجات):** 
  - نص صريح (Plain Text) مُنقذ من الصورة `ocr_text` ليتم تمريره كبديل.

## 🧩 الخطوة الثالثة: التمزيق التقاطعي (Semantic Segmentation)
📍 **الملف:** `section_segmenter.py`

- **الـ Input (المُدخلات):** 
  - النص الكامل المتسلسل (آتياً من הـ Spatial أو הـ OCR).
- **الخوارزميات والـ Processing (المعالجة):**
  - **الخوارزمية الأولى (Normalization):** تحويل النصوص لأحرف صغيرة (Lowercase) وتمرير `Regex (\W+)` لمسح علامات الترقيم من العناوين لتوحيدها.
  - **الخوارزمية الثانية (Dictionary/Regex Match):** بحث ذو تعقيد سريع O(1) لمقارنة كل سطر بأسماء الأقسام المُتعارف عليها.
  - **الخوارزمية الثالثة (Semantic Cosine Similarity):** إذا وجد سطراً مشبوهاً لا يبدأ بنقطة (`_looks_like_bullet`)، يمرره لمودل `SentenceTransformer`. وتُحسب المسافة הזاوِية رياضياً بين هذا السطر والمراجع. إذا تعدت التطابق 0.82، يتم تقطيع النص ابتداءً من هذه النقطة وإرساله لحافظة مستقلة.
- **الـ Output (المُخرجات):** 
  - `SegmentationResult`: مصفوفة قواميس معزولة (هاش ماب) تحتوي على نصوص جاهزة في مفاتيح כמו `Profile`, `Experience`, `Skills`.

## 📞 الخطوة الرابعة: استخلاص الهويات (Contact Extraction)
📍 **الملف:** `contact_extractor.py`

- **الـ Input (المُدخلات):** 
  - النص الكامل أو مقطع الـ `Profile`.
- **الخوارزميات والـ Processing (المعالجة):**
  - **الخوارزمية:** تعتمد حصرياً على الـ (Deterministic RegEx Expressions).
  - باترن مخصص لاصطياد الروابط (LinkedIn / GitHub)، وباترن دولي لالتقاط الهواتف (Phone numbers)، وآخر للإيميلات.
- **الـ Output (المُخرجات):** 
  - قاموس `dict` به بيانات الاتصال صافية من كل الشوائب للوصول للمرشح.

## 🧠 الخطوة الخامسة: محرك الذكاء والכיانات (NER & Canonicalization)
📍 **الملفات:** `advanced_ner.py` و `canonicalizer.py`

- **الـ Input (المُدخلات):** 
  - الـ Strings المُمزقة (بالتحديد أجزاء `profile_summary` و `skills`).
- **الخوارزميات والـ Processing (المعالجة):**
  - **التكنولوجيا:** `HuggingFace Transformers` محمل بموديل (Token Classification). و `RapidFuzz`.
  - **المعالجة في NER:** يتم استخدام التكميم (INT8 Dynamic Quantization) لتحويل أوزان המودל وقت التنفيذ لتخفيف الحمل على معالج הـ CPU. يأخذ המودל الكلمات بسياق 3 كلمات قبلها وبعدها، ويُصنفها لـ `Skills` أو `Roles` أو `Orgs`.
  - **المعالجة في الـ Canonicalization:**
    1. يتم تجاهل أي مهام تحتوي على أفعال (`ACTION_VERBS` hashset) لمنع تصنيف "Engineered" كـ مهارة!
    2. يُمرر المخرجات على مكتبة `RapidFuzz` التي تستخدم مسافة التعديل الرياضية (Levenshtein Distance) لمعرفة نسبة الخطأ البشري.
    3. إذا فشل، يُمرر لـ `SemanticEmbedder` بتشغيل عمليات مجمعة `Numpy Batch Vectors` لحساب أقرب مهارة منطقية بعتبة 0.85.
- **الـ Output (المُخرجات):** 
  - مصفوفة نظيفة من نوع `CanonicalSkill` ومصفوفات بالمسميات الوظيفية والأماكن خالية من التكرار (Deduplicated).

## 📅 الخطوة السادسة: الهندسة الزمنية (Experience Engine)
📍 **الملفات:** `experience_engine.py` (בاستدعاء محلي للـ NER)

- **الـ Input (المُدخلات):** 
  - نص قسم الخبرات (`experience_text`).
- **الخوارزميات والـ Processing (المعالجة):**
  - **استخراج الزمن (Temporal Extraction):** محاولة قراءة `Regex` لصيغ التواريخ المختلفة.
  - **خوارزمية دمج التواريخ المتداخلة (`_merge_date_ranges`):** مصفوفة خوارزمية (O(N log N)) تقوم بترتيب التواريخ تصاعدياً ثم مقارنة الـ `End_Date` الحالي بالـ `Start_Date` للوظيفة الأخرى. إذا حصلا في وقت واحد، يتم إمتصاصهما زمنياً لمنع العد המُزدوج!
  - **تحليل الجودة (Action/Health Scoring):** يتم قراءة النقاط (Bullets). إذا تم إيجاد مسافة فراغ (Gap) تتعدى 180 يوماً متواصلة، تُسجل כـ `red_flag`. يتم حساب كلمات الـ Leadership لبناء Score.
- **الـ Output (المُخرجات):** 
  - كائنات `ExperienceItem` متكاملة: كل وظيفة لها تاريخ بداية، نهاية، التقنيات التي استخدمت فيها *بالتحديد*، والمسمى، وصافي مدة المهارة.

## 🎻 الخطوة السابعة والأخيرة: الجمع النهائي (The Orchestration)
📍 **الملف:** `orchestrator.py` و `schema.py`

- **الـ Input (المُدخلات):** 
  - جميع המخرجات מن الخطوات 1 إلى 6.
- **الخوارزميات والـ Processing (المعالجة):**
  - **خوارزميات الاستنتاج المُركبة (Composite Heuristics):** دالة `_infer_seniority` تأخذ (عدد السنوات الصافي) واسم الوظيفة وتقوم بمعادلة توزيع الوزن لتحديد ما إذا كان الشخص (Junior أو Mid أو Senior).
  - **ضمان سلامة הبيانات (Pydantic Serialization):** إمرار كل المكونات عبر `CVParseResult` Schema لضمان التزام أنواع הبيانات.
  - **إدارة الذاكرة (Memory Cleanup):** بمجرد الانتهاء، يُفتح `threading.Lock()` للمستخدم அடுத்த، وتُستدعى `gc.collect()` لتنظيف مخلفات הـ PyMuPDF و SentenceTransformer من הـ Memory RAM.
- **الـ Output (المُخرجات):** 
  - `CVParseResult`: الهيكل الذهبي والـ JSON المُحكم الذي تستلمه الطبقات الأعلى (Mobile & Web APIs) ليعرض للمُستخدم الواجهة النهائية المنظمة.
